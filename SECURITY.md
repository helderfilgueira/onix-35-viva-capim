# Segurança e reporte

O laboratório é demonstração local. O piloto só deve receber dados reais após os controles e procedimentos descritos no runbook. Não abrir issue pública com senha, token, telefone, base de dados, URL assinada ou detalhes que exponham visitantes.

Se o repositório disponibilizar reporte privado de vulnerabilidade na aba Security, use esse canal. Caso contrário, solicite ao responsável do projeto um canal privado sem publicar o detalhe sensível. Nenhum endereço de suporte ou prazo de resposta é inventado neste documento.

Ao reportar, informe versão/commit, componente, passos mínimos, impacto observado e evidência sanitizada. Não explorar contas de terceiros ou dados reais para provar uma falha. A equipe deve restringir a função afetada, preservar evidências privadas e validar correção antes de retomada.

Riscos conhecidos: piloto sem OTP não verifica posse do telefone; agregado mínimo não garante anonimização; mapa não certifica acesso físico; planos gratuitos não garantem disponibilidade. Consulte [privacidade](docs/PRIVACIDADE.md) e [runbook](docs/RUNBOOK.md).
